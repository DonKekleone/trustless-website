Primary Lifecycle

From definition to resolution.

Product implementations can add detail, but the core lifecycle separates agreement creation, funding, active performance and terminal resolution.

Created

The parties, payment amount, milestones, deadlines and other parameters are defined.

Awaiting funding

The system prepares payment instructions, but the agreement is not yet treated as funded.

Funded

Expected XRP Ledger activity has been verified and associated with the agreement.

Active

Work, milestone timers and recorded participant actions are in progress.

Review or revision

Delivered work moves through the approval and correction rules available to the current milestone.

Resolved

Release, refund, cancellation or expiry produces a terminal contract outcome.

Milestone State

A contract can contain smaller state machines.

Each milestone can progress independently while remaining part of the larger agreement.

Work

The provider operates under the milestone scope and delivery window.

Review

Submitted work enters a defined period for approval or an available revision request.

Revision

Corrections occur inside a bounded revision period when the agreement permits them.

Ready

The milestone reaches a state where the applicable settlement action can proceed.

Complete

The milestone payment has been released and its active workflow is closed.

Refunded or cancelled

Eligible value returns or the remaining stage closes according to the contract rules.

Transition Discipline

A transition needs a valid cause.

User action

Approval, revision requests, extension decisions and cancellations can trigger permitted transitions.

Verified ledger activity

Funding or settlement evidence can move the application into the corresponding payment state.

Timer event

Expiry or elapsed review and revision windows can change available actions.

Product rule

Trustless Network and Enforcer use different conditions while preserving explicit state and defined outcomes.
